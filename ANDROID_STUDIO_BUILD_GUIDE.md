# Building an APK with Android Studio

This guide will walk you through the process of building an APK for your Blip Market Place app using Android Studio after generating the native code with Expo prebuild.

## Prerequisites

1. Android Studio installed (https://developer.android.com/studio)
2. Java Development Kit (JDK) 11 or newer
3. Android SDK installed and configured (usually installed with Android Studio)

## Step 1: Open the Android Project

1. Launch Android Studio
2. Select "Open an existing Android Studio project"
3. Navigate to your project directory and select the `android` folder that was generated by the prebuild process
4. Wait for Android Studio to sync the project (this may take a few minutes)

## Step 2: Resolve Any Gradle Issues

If you encounter any Gradle sync issues:

1. Look at the error messages in the "Build" tab at the bottom of Android Studio
2. Common issues include:
   - Missing SDK components: Install them via Tools > SDK Manager
   - Gradle version mismatch: Update Gradle in File > Settings > Build, Execution, Deployment > Gradle
   - Memory limitations: Increase Gradle memory by adding `org.gradle.jvmargs=-Xmx4g` to `gradle.properties`

## Step 3: Build a Debug APK (Optional)

To test your app before creating a signed release:

1. Select "Run" > "Run 'app'" from the menu
2. Choose a connected device or create a new emulator
3. Android Studio will build and install a debug version of your app

## Step 4: Create a Signed Release APK

1. In Android Studio, go to Build > Generate Signed Bundle / APK
2. Select "APK"
3. Create a new keystore or use an existing one:
   - To create a new keystore:
     - Click "Create new..."
     - Choose a location to save your keystore file (e.g., `my-release-key.keystore`)
     - Enter a password for the keystore
     - Enter an alias name for the key (e.g., "blip-market-place-key")
     - Enter a password for the key (can be the same as the keystore password)
     - Fill in the certificate information (Name, Organization, etc.)
     - Click "OK"
   - To use an existing keystore:
     - Enter the path to your keystore file
     - Enter the keystore password
     - Enter the key alias
     - Enter the key password
4. Click "Next"
5. Select "release" as the build variant
6. Check both "V1 (Jar Signature)" and "V2 (Full APK Signature)"
7. Choose a destination folder for your APK
8. Click "Finish"

## Step 5: Locate Your APK

Once the build process completes, you can find your APK at:
```
android/app/build/outputs/apk/release/app-release.apk
```

## Step 6: Install and Test Your APK

1. Transfer the APK to your Android device (via USB, email, cloud storage, etc.)
2. On your device, navigate to the APK file and tap it to install
3. If prompted, enable installation from unknown sources in your device settings
4. Test your app thoroughly to ensure everything works as expected

## Troubleshooting

### Common Issues

1. **Signing Issues**:
   - Double-check your keystore information
   - Make sure you're using the correct passwords
   - If you lose your keystore or forget the passwords, you'll need to create a new one and increment the versionCode in app.json

2. **Build Failures**:
   - Check the error messages in the Build output window
   - Make sure all dependencies are properly installed
   - Verify that your Android SDK is properly configured

3. **Installation Issues**:
   - Make sure your device has "Install from unknown sources" enabled
   - Check that you have enough storage space on your device
   - Verify that you're installing the correct APK (release, not debug)

### Important Notes

- **Keep your keystore safe**: You'll need the same keystore for all future updates to your app
- **Remember your keystore passwords**: There's no way to recover them if lost
- **Increment versionCode**: Each time you release a new version, increment the versionCode in app.json

## Next Steps

After successfully building your APK, you can:

1. Distribute it to testers via email, file sharing, or a testing platform
2. Upload it to the Google Play Store (requires a developer account)
3. Share it on your website or other distribution channels
